# LawRAG PageIndex 机制与数据导入方案

## 概述

为 lawrag 建立 pageindex 机制，用于在嵌入向量/BM25 混合召回检索后，进行详细的结构化法条查找。同时添加原始法条数据导入方法，将 testdoc/ 下的法律文本按法条粒度存储到数据库，再嵌入到现有 RAG 系统。

## 设计原则

- testdoc 数据集中，除宪法外所有文件都是扁平的法条逐行格式（`《XX法》第X条规定，{内容}`），无章节/节标题
- 因此 pageindex 采用**扁平存储**，不构建多级树形结构
- 复用现有 `DocumentSource` 作为法律来源标识，新建 `LawArticle` 表存储原始法条，通过 source_id 关联

## 1. 新数据库表：`law_articles`

在 `backend/lawrag/database/tables.py` 新增 SQLModel：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID (PK, uuidv7) | 主键 |
| `source_id` | UUID (FK → document_source.id, indexed) | 关联来源 |
| `law_name` | str (indexed) | 法律名称，如"中华人民共和国民法典" |
| `article_number` | int | 法条编号（第X条） |
| `content` | Text | 法条正文内容 |
| `metadata` | JSONB | 扩展信息（如施行日期等） |

索引：
- `idx_law_articles_source` — source_id
- `idx_law_articles_law_name` — law_name
- `uq_law_article` — (law_name, article_number) 唯一约束

## 2. PageIndex 检索模块：`backend/lawrag/database/pageindex.py`

新增 `LawPageIndex` 类，提供以下方法：

| 方法 | 功能 |
|------|------|
| `aimport_from_dir(dir_path)` | 批量解析 .txt 文件并存入 law_articles |
| `aimport_file(file_path)` | 导入单个 .txt 法律文件 |
| `aget_by_law_article(law_name, article_number)` | 按法律名+法条号精确查找 |
| `aget_law_articles(law_name, start, end)` | 按法条号范围查询 |
| `alist_laws()` | 列出所有已导入的法律名称 |
| `aenrich_search_results(documents)` | 将向量检索得到的 Document 结果，补充对应 LawArticle 的结构化信息 |

检索增强流程：
1. 向量/BM25 混合搜索 → 得到 Document 分块列表
2. 对每个分块，通过 source → law_name 找到对应的 LawArticle
3. 返回法条的结构化表示（law_name + article_number + content）

## 3. 数据导入模块：`backend/lawrag/documents/lawparser.py`

两种解析器：

### 3a. `StandardLawParser`（格式 B，用于绝大多数法律）
- 逐行正则匹配：`《(.+?)》第([一二三四五六七八九十百千]+)条规定，(.+)。`
- 将中文数字转换为整数 article_number
- 输出：[(law_name, article_number, content), ...]

### 3b. `ConstitutionParser`（格式 A，仅用于宪法）
- 跳过标题块和目录行
- 检测章节标题行（`第X章`/`第X节`），记录在 metadata 中
- 检测法条行（`第X条 {content}`），合并多行 content
- 以 `序言` 标记为 article_number=0

### 3c. `LawImporter` 统一入口
- 根据文件名或内容判断使用哪个解析器
- 调用 `aconvert_file` 转格式 → `LawParser.parse` → 存入 `law_articles` 表
- 同时创建对应的 `DocumentSource` 记录

## 4. 与现有 RAG 系统的集成

### 4a. 修改 `backend/lawrag/routers/rag.py`
- 新增 `POST /api/pageindex/import` — 导入法条（接收 dir_path 或 file_path）
- 新增 `GET /api/pageindex/laws` — 列出已导入法律
- 新增 `GET /api/pageindex/laws/{law_name}/articles` — 查询法条列表
- 新增 `GET /api/pageindex/laws/{law_name}/articles/{article_number}` — 精确查找法条

### 4b. 增强搜索响应
- `SearchRequest`/`SearchResponse` 中新增 `include_pageindex: bool` 选项
- 开启后在搜索结果中附带对应的法条结构化信息

### 4c. AI 工具集成
- 在 `backend/lawrag/tools/base.py` 新增 `search_law_articles_base` 工具
- 注册到 `rag_toolset` 中

## 5. CLI 命令扩展

在 `backend/lawrag/__main__.py` 新增 `lawrag pageindex` 子命令组：

```
lawrag pageindex import <path>    # 导入法律文件（文件或目录）
lawrag pageindex list              # 列出已导入的法律
lawrag pageindex show <law>        # 查看某部法律的法条列表
lawrag pageindex search <law> <q>  # 在某部法律中搜索法条
```

## 7. 验证方案

1. **单元测试**：`uv run pytest tests/test_lawparser.py` — 验证标准格式和宪法解析
2. **集成测试**：`uv run pytest tests/test_pageindex.py` — 验证导入→存储→检索全链路
3. **手动验证**：
   - `lawrag pageindex import testdoc/` — 导入全部法律
   - `lawrag pageindex list` — 确认法律列表
   - `lawrag search "监护人的职责"` — 混合检索 + pageindex 增强结果
   - 启动 FastAPI，调用 `/api/pageindex/laws` 等端点验证
4. **类型检查**：`uv run ty check backend/lawrag/`
5. **格式检查**：`uv run ruff check backend/lawrag/`

## 8. 外部依赖

本方案**不引入新依赖**，所有功能基于现有依赖实现：
- `sqlmodel` / `sqlalchemy` — 新表定义
- `re` (stdlib) — 法条解析正则
- 中文字数转换函数自实现（`一二三→1,2,3` 等）
